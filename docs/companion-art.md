# Companion artwork

The Today screen shows a companion whose mood follows the day's progress:
she waits while the plan is open and cheers up with every tick.

Out of the box the app draws a built-in stand-in, so the mechanic works before
any artwork exists. To replace it, drop an art pack into
`app/src/main/assets/companion/<pack-id>/`. No code changes are needed.

## pack.json

```json
{
  "name": "Ann",
  "options": {
    "hair":   ["long", "short"],
    "outfit": ["casual", "sport"],
    "body":   ["slim", "athletic"]
  },
  "frames": {
    "SAD":         "{hair}_{outfit}_{body}_sad.webp",
    "BORED":       "{hair}_{outfit}_{body}_idle.webp",
    "INTERESTED":  "{hair}_{outfit}_{body}_smile.webp",
    "HAPPY":       "{hair}_{outfit}_{body}_happy.webp",
    "CELEBRATING": "{hair}_{outfit}_{body}_dance.json"
  }
}
```

- `options` drives the pickers in Settings. Leave it out for a pack with a
  single look — then write plain file names in `frames`.
- `frames` maps a mood to a file in the same folder. `{key}` is replaced with
  the chosen option. A `.json` file is played as a **Lottie** animation,
  anything else is shown as a still image (`.webp` and `.png` work).
- A missing mood falls back to the closest one, a missing file falls back to
  the built-in stand-in — a partial pack never crashes the screen.

## Placement and image size

Settings offers two placements, and they want different artwork.

**Bottom** (default) — she stands in the lower 55% of the screen, the whole
frame is fitted, nothing is cropped.

- 1024 x 1536, portrait 2:3
- the figure fills the frame, feet right at the bottom edge, no wide margins

**Full screen** — she becomes the background. The image is scaled to cover the
whole screen and anchored to the bottom, so the left and right edges get
trimmed on anything wider than the phone.

- 1080 x 2400, portrait 9:20, or anything taller than 2:3
- keep her head about a third of the way down: the date, the progress bar and
  the first card sit over the top of the screen
- keep faces and detail away from the left and right edges, they get cropped
- the top of the screen is dimmed with a gradient so the header stays readable

Both modes need a transparent background, and both are fine with the same five
moods — only the framing differs.

## Moods

| Mood | When it shows |
|---|---|
| `SAD` | nothing done and the reminder time has passed |
| `BORED` | nothing done yet, the day is still young |
| `INTERESTED` | at least one challenge ticked off |
| `HAPPY` | every must-do challenge is closed |
| `CELEBRATING` | the whole day is closed |

## Where to get the artwork

Nothing here is generated by the app — you supply the files.

- **Lottie** (`.json`) — vector animation exported from After Effects with
  Bodymovin, or drawn in [LottieFiles](https://lottiefiles.com). Small files,
  scales to any screen. Already wired up.
- **Still frames** (`.webp`) — the fastest route to a realistic look, and the
  only one that needs no code at all: five images per look, dropped into the
  pack folder. Commissioned art, a 3D render and generated images all fit.
  Keep them under ~300 KB each.
- **Rive** (`.riv`) — the best fit if you want real blending between moods
  rather than swapped frames. It needs `app.rive:rive-android` and a renderer
  next to `LottieCompanion` in `ui/companion/CompanionView.kt`; moods map onto a
  state machine input. Note two things: a `.riv` file is a binary export that
  can only be authored in the Rive editor, and Rive draws vectors, so the result
  is stylised rather than photorealistic.
- **3D avatar** — for genuinely realistic and deeply customizable looks, use a
  glTF avatar (for example from Ready Player Me) rendered with Filament or
  SceneView. This is the heaviest option: it adds tens of megabytes to the APK
  and needs animation clips per mood.

Whichever you pick, only `CompanionView` changes — the mood logic in
`domain/Companion.kt` and the settings stay as they are.
